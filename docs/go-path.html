my_infra Go が見つからない

nix-darwin 導入の翌日 · 2026-09-10

Go を入れたのに command not found

公式インストーラ (.pkg) で Go 1.27.1 を入れた。インストールは成功している。それなのに go が見つからない。
壊したのは Go ではなく、前日に入れた nix-darwinだった。

  1. ✓ 完了 1. Go をインストール /usr/local/go に配置された
  2. ▶ 今ここ 2. PATH に乗らない /etc/paths.d が読まれていない
  3. ○ 未 3. 原因を突き止める nix-darwin と path_helper
  4. ○ 未 4. nix で入れ直す hosts/mini.nix に 1 行

結論: .pkg で入れるのをやめて、nix-darwin の宣言に加える。

01 — 状況確認

入ってはいる。呼べていないだけ

まず「本当にインストールされているか」と「PATH に含まれているか」を切り分ける。フルパスで叩けば動くなら、問題は PATH 側にある。

$ which go
go not found

$ /usr/local/go/bin/go version
go version go1.27.1 darwin/arm64          # 本体は無傷

$ pkgutil --pkg-info org.golang.go
package-id: org.golang.go
version: go1.27.1                              # インストーラの記録もある

$ cat /etc/paths.d/go
/usr/local/go/bin                              # PATH 追加用のファイルも正しい

$ echo $PATH | tr ':' '\n' | grep go
(何も出ない)                                  # なのに PATH に入っていない
ここまでで分かること

Go 側は全部そろっている。インストーラが置いた /etc/paths.d/go を 誰も読んでいない。読むはずの仕組みを疑う。

02 — 仕組み

macOS は path_helper で /etc/paths.d を PATH に足す

.pkg 形式のインストーラは /etc/paths.d/ に 1 行のファイルを置くだけで、PATH の編集はしない。実際に PATH へ足すのは、ログインシェル起動時に /etc/zprofile から呼ばれる path_helper の役目。

ログインシェル (zsh -l) が起動
   │
   ├─ /etc/zshenv
   ├─ /etc/zprofile                # ← macOS 標準版はここで path_helper を呼ぶ
   │     │
   │     └─ eval `/usr/libexec/path_helper -s`
   │            │
   │            ├─ /etc/paths      を読む   # /usr/bin /bin /usr/sbin /sbin /usr/local/bin
   │            └─ /etc/paths.d/*  を読む   # go, Wireshark, com.vmware.fusion.public ...
   │                                        ↑ ここで /usr/local/go/bin が PATH に入るはず
   ├─ /etc/zshrc
   └─ ~/.zshrc
macOS 標準の /etc/zprofile

if [ -x /usr/libexec/path_helper ]; then eval `/usr/libexec/path_helper -s`; fi という 3 行が本体。これがあるから .pkg で入れたツールは何もしなくても使える。

nix-darwin の /etc/zprofile

/etc/static/zprofile への symlink に置き換わる。中身は zprofile.local を読むだけで、path_helper の呼び出しがない。

03 — 原因

前日の switch が /etc/zprofile を差し替えていた

$ ls -la /etc/zprofile*
lrwxr-xr-x  root  wheel   9月  9 21:08 /etc/zprofile -> /etc/static/zprofile     # nix-darwin 版
-r--r--r--  root  wheel   8月 13 11:51 /etc/zprofile.before-nix-darwin            # 退避された元ファイル

$ grep -rn path_helper /etc/static/
(何も出ない)                                     # nix-darwin の生成物には一切ない

$ grep -n path_helper /etc/zprofile.before-nix-darwin
11:	eval `/usr/libexec/path_helper -s`          # 元ファイルにはある

$ date -r $(pkgutil --pkg-info org.golang.go | awk '/install-time/{print $2}')
2026年 9月10日 00時27分                          # Go を入れたのは差し替えの 3 時間後
日時出来事結果
9/9 21:08 darwin-rebuild switch (OrbStack 導入) /etc/zprofile が nix-darwin 版になり、path_helper が呼ばれなくなる
9/10 00:27 Go 1.27.1 の .pkg をインストール /etc/paths.d/go は作られたが、誰にも読まれない
巻き添え

Go だけの問題ではない。/etc/paths.d/ にある VMware Fusion と Wireshark の CLI も同じ状態になっている。今後 .pkg で入れるツールはすべて同じ道をたどる。

04 — なぜ呼ばないのか

これは nix-darwin のバグではなく設計

path_helper は PATH を 組み直す。/etc/paths の中身 (システムのディレクトリ) を先頭に置き、既存の PATH はその後ろに回す。nix の狙いと真っ向から衝突する。

nix-darwin が望む順序 ~/.nix-profile/bin
/run/current-system/sw/bin
/usr/local/bin /usr/bin /bin ...

nix で入れたコマンドが システム同梱のものより先に見つかる。同名コマンドを nix 側で差し替えるための前提。

path_helper を通したあとの順序 /usr/bin /bin /usr/sbin /sbin /usr/local/bin
/usr/local/go/bin ...
~/.nix-profile/bin /run/current-system/sw/bin

nix のパスが 末尾に押しやられる。/usr/bin の古い zsh や bash が nix 版に勝ってしまう。

だから

nix-darwin は path_helper を意図的に外し、/etc/zshenv から自前の set-environment で PATH を固定している。path_helper を復活させるのは、この設計を打ち消す行為になる。

05 — 選択肢

直し方は 4 つ。どこまで nix に任せるか

方法やること直る範囲評価
~/.zshrc に追記 export PATH="$PATH:/usr/local/go/bin" Go だけ 手軽だが、nix の外に設定が散らばる
environment.systemPath nix-darwin の設定に /usr/local/go/bin を列挙 Go だけ .pkg 版をどうしても使うならこれ。ツールごとに追記が要る
path_helper 復活 ~/.zprofile などで呼び直す /etc/paths.d 全部 範囲は広いが、PATH の順序が崩れて nix と衝突する
nix で Go を入れる environment.systemPackages に pkgs.go_1_27 Go (PATH 問題そのものが消える) 推奨。 nix-darwin を使う以上、ツールも nix で入れるのが筋

推奨を選ぶ理由

Go は /run/current-system/sw/bin に入る。ここは すでに PATH にあるので、PATH を触る必要がなくなる。バージョンは flake.lock で固定され、別のマシンでも同じ結果になる。

同類の問題への答え

nixpkgs にあるツールは systemPackages へ。GUI アプリは nix-darwin の homebrew モジュールで cask 管理する。Homebrew の PATH は ~/.zprofile の brew shellenv で通っている。

対処 1 / 2

hosts/mini.nix に 1 行足す

これを追記
environment.systemPackages = [ pkgs.go_1_27 ];

関数の引数に pkgs を受け取る必要があるので、先頭の { ... }: を { pkgs, ... }: に変える。

# hosts/mini.nix
-{ ... }:
+{ pkgs, ... }:
 {
   nixpkgs.hostPlatform = "aarch64-darwin";
   nix.enable = false;
   my-infra.orbstack.enable = true;

+  # 開発ツール。nix で入れると /run/current-system/sw/bin に配置され PATH に乗る。
+  environment.systemPackages = [ pkgs.go_1_27 ];

   system.stateVersion = 6;
 }

なぜ go ではなく go_1_27 か

ロック済みの nixpkgs では pkgs.go が 1.26.7 を指す。.pkg で入れたのと同じ 1.27.1 にそろえるため、系列を明示した。go のままだと nix flake update のたびに系列が変わりうる。

適用前に確かめる

nix eval --raw '.#darwinConfigurations.mini.pkgs.go_1_27.version' で何が入るかを先に見ておく。orbstack.nix の systemPackages とは リストが結合されるので、上書きの心配はない。

対処 2 / 2

適用して、シェルを開き直す

これを実行
$sudo darwin-rebuild switch --flake .#mini

my_infra のルートで実行する。sudo が要るのは /etc と /run/current-system を書き換えるため。

$ sudo darwin-rebuild switch --flake .#mini
building the system configuration...
setting up /etc...
...
$ exec zsh -l                               # PATH は起動時にしか読まれない (前回と同じ)

$ which go
/run/current-system/sw/bin/go              # /usr/local/go ではなく nix 側
$ go version
go version go1.27.1 darwin/arm64
$ readlink /run/current-system/sw/bin/go
/nix/store/akbps6r...-go-1.27.1/bin/go
.pkg 版はもう要らない

/usr/local/go と /etc/paths.d/go はどこからも参照されなくなった。残しておいても害はないが、消すなら sudo rm -rf /usr/local/go /etc/paths.d/go。pkgutil --forget org.golang.go でインストーラの記録も消せる。

06 — 確認

ここまで通れば完了

  • /usr/local/go/bin/go version が動く (本体は無事)
  • ls -la /etc/zprofile が /etc/static/zprofile への symlink になっている (原因の確定)
  • hosts/mini.nix に pkgs.go_1_27 を追記し、{ pkgs, ... }: に変える
  • nix build .#darwinConfigurations.mini.system が通る
  • sudo darwin-rebuild switch --flake .#mini がエラーなく終わる
  • exec zsh -l のあと which go が /run/current-system/sw/bin/go を返す
  • 不要なら /usr/local/go と /etc/paths.d/go を削除する

上 6 つは実施済み。最後の削除は任意。

07 — 切り分け

同じ症状が出たときの見分け方

症状原因対処
.pkg で入れた CLI が command not found /etc/paths.d が読まれていない nixpkgs にあれば systemPackages へ。なければ environment.systemPath に追記
フルパスなら動く PATH の問題であって、インストールは成功している 再インストールしない。PATH 側を見る
switch 後も同じシェルで通らない PATH は起動時にしか読まれない exec zsh -l
pkgs.go が古い nixpkgs の go は 1 世代前を指すことがある go_1_27 のように系列を明示する / nix flake update
プロジェクトごとに Go の版を変えたい システム全体の設定では 1 つしか置けない 各リポジトリの flake.nix に devShell を書き nix develop
適用後に調子が悪い 直前の変更が原因 sudo darwin-rebuild --rollback

08 — 教訓

nix-darwin を入れた日から、インストール方法は 1 つに絞る

.pkg インストーラは信用しない

「インストール完了」と出ても、PATH に乗せる仕組みが nix-darwin 環境では動いていない。入れた直後に which で確かめる癖をつける。

ツールの置き場は 2 つだけ

CLI は environment.systemPackages、GUI は homebrew.casks。どちらも my_infra の宣言に残るので、次のマシンでも同じ環境が再現できる。

調べる順番

フルパスで動くか → /etc/paths.d にあるか → /etc/zprofile が symlink か。この 3 手で「nix-darwin が原因」まで 1 分で着く。

元に戻したくなったら

macOS 標準の設定は /etc/zprofile.before-nix-darwin などに退避されている。darwin-uninstaller がこれを戻す。

nix-darwin の適用手順は docs/darwin-rebuild.html、適用後の PATH 反映は docs/orbstack-startup.html を参照。 — ysksm/my_infra
