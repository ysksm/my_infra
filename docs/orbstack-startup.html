2 回目以降が短くなる理由

darwin-rebuild 自体がここに入った。今後は sudo darwin-rebuild switch --flake .#mini だけでよい。

03 — 原因

PATH はシェルの起動時にしか読まれない

nix-darwin は /etc/zshenv を書き換えて PATH を設定する。ただしこれは 新しいシェルが起動したときに読まれるファイル。switch を打ったシェルは、それより前に起動している。

新しい zsh が起動
   │
   ├─ /etc/zshenv を読む          # nix-darwin が作った symlink
   │     │
   │     └─ . /nix/store/9fsy5zj...-set-environment
   │            │
   │            └─ export PATH=$HOME/.nix-profile/bin:/run/current-system/sw/bin:...
   │                                                   ↑ ここで docker が見つかるようになる
   ├─ /etc/zshrc を読む
   └─ ~/.zshrc を読む             # 個人設定は最後。ここでの上書きが勝つ
つまり

設定ファイルはもう書かれている。読み込ませればいいだけで、再インストールも再適用も要らない。

対処 1 / 3

シェルを開き直す

これを実行
$exec zsh -l

今のウィンドウのまま、zsh を起動し直す。新しいターミナルを開いても結果は同じ。

$ exec zsh -l
$ docker -v
Docker version 29.4.0, build 9d7ad9f   # 通るようになる

それでも通らないときは

~/.zshrc で PATH を丸ごと上書きしている可能性がある。個人設定は /etc/zshenv より後に読まれるので、そちらが勝つ。

確かめ方

echo $PATH | tr ':' '\n' | grep current-system で /run/current-system/sw/bin が含まれているかを見る。

04 — 次の壁

CLI はあっても、デーモンがいない

PATH が通っても、まだコンテナは動かない。docker は命令を送るだけのコマンドで、受け取って実行する側が別に必要になる。

今そろっているもの docker / orbctl / kubectl

コマンド (クライアント)。「コンテナを起動して」と伝える役。

足りないもの OrbStack.app

Linux VM と Docker デーモン。実際にコンテナを動かす役。まだ起動していない。

$ pgrep -x OrbStack
(何も出ない)   # 未起動
Nix でできるのはここまで

Nix が保証するのは「アプリとコマンドを正しい場所に置くこと」。起動は Nix の仕事ではないので、初回は自分で立ち上げる。

対処 2 / 3

OrbStack を起動する

これを実行
$open "/Applications/Nix Apps/OrbStack.app"

パスにスペースが入るので引用符が要る。Finder から起動しても同じ。

初回だけ聞かれること

特権ヘルパーのインストールで管理者パスワードを求められる。ネットワーク設定に必要なもので、正常な挙動。

起動できたかの確認

docker ps が空のテーブルを返せば成功。エラーが出るなら、まだ起動中か未起動。

なぜ普通の /Applications ではないのか

nix-darwin が管理するアプリは /Applications/Nix Apps にまとめられる。手で入れたアプリと混ざらないようにするため。Spotlight や Launchpad からは通常どおり探せる。

05 — 紛らわしい点

docker compose と docker-compose の違い

起動前の今は、スペース版だけが使えない。ハイフン版は動く。同じものに見えて、呼ばれ方が違う。

$ docker compose version
docker: unknown command: docker compose

$ docker-compose version
Docker Compose version v5.1.2
書き方正体探し先今の状態
docker-compose 独立した実行ファイル PATH 動く
docker compose docker のサブコマンド (プラグイン) ~/.docker/cli-plugins まだ空
対処は不要

~/.docker/cli-plugins は OrbStack が初回起動時に自分で用意する。手で作る必要はない。起動後は両方の書き方が使える。

対処 3 / 3

GitLab を起動する

これを実行
$cd gitlab && docker compose up -d

初回はイメージの取得に時間がかかる。GitLab は起動完了までさらに数分かかる。

Web

http://127.0.0.1:8080

SSH

ポート 2222

データの置き場

~/srv/gitlab の config / logs / data

データがリポジトリの外にある理由

gitlab-secrets.json や SSH ホスト鍵が含まれるため。このリポジトリは公開されているので、実データは ~/srv/gitlab に置き、compose からは ${HOME}/srv/gitlab として参照している。

08 — 補足

ついでに変わったこと

zsh のプロンプトが変わる

nix-darwin の /etc/zshrc が prompt suse を設定する。~/.zshrc は後に読まれるので、自分のプロンプト設定があればそちらが優先される。

再起動しても復元される

org.nixos.activate-system という launchd サービスが作られた。起動のたびに設定を適用し直す。

/run が作られた

macOS はルート直下に書き込めないため、/etc/synthetic.conf という仕組みで /run を用意している。

Nix 本体は Determinate のまま

nix.enable = false; にしたので、Nix 自体の設定は /etc/nix/nix.custom.conf と determinate-nixd が担当する。

コマンドの各パーツの意味は docs/darwin-rebuild.html を参照。 — ysksm/my_infra
