Redmine を macOS で回す

OrbStack の上で redmine:6 と postgres:16 を動かし、./redminectl ひとつで起動・バックアップ・更新・復旧までを回す。
コンテナの中身は覚えなくていい。覚えるのはサブコマンドの名前だけ。

  1. 1 · 一度 準備 OrbStack が動いている
  2. 2 · 一度 初回セットアップ redminectl setup
  3. 3 · 毎日 日常運用 status / logs / restart
  4. 4 · 毎晩 バックアップ backup を launchd で
  5. 5 · 月 1 更新 update
  6. 6 · 有事 復旧 restore <dir>

全体像

動いているのは 4 層。触るのは一番上だけ

macOS の上で OrbStack が Docker デーモンを動かし、その上で compose が 2 つのコンテナを並べる。状態を持つのは ~/srv/redmine と redmine/.env の 2 か所。それ以外は消しても作り直せる。

macOS (mini)
 │
 ├─ OrbStack ─────────────── Docker デーモン。ログイン時に自動起動させておく
 │    │
 │    └─ docker compose ──── redmine/docker-compose.yaml
 │         │
 │         ├─ redmine     redmine:6      :3000 → http://127.0.0.1:3000
 │         │     ├─ /usr/src/redmine/files          ← ~/srv/redmine/files    (添付ファイル)
 │         │     ├─ /usr/src/redmine/plugins        ← ~/srv/redmine/plugins
 │         │     └─ /usr/src/redmine/public/themes  ← ~/srv/redmine/themes
 │         │
 │         └─ redmine-db  postgres:16    (ポート非公開。redmine からだけ見える)
 │               └─ /var/lib/postgresql/data       ← ~/srv/redmine/db
 │
 └─ redmine/.env ─────────── DB パスワードと secret_key_base。git 管理外
OrbStack

Docker デーモンそのもの。止まっていると docker コマンドが全部失敗する。restart: always のコンテナは OrbStack が上がれば勝手に戻る。

redmine:6

起動のたびに entrypoint が db:migrate を流す。更新後の migration は手動でやらなくていい。

postgres:16

healthcheck が通るまで Redmine は起動しない。バックアップは pg_dump をコンテナ内で実行して取る。

1 — 準備

OrbStack が動いていれば、それで足りる

nix-darwin で OrbStack を入れた状態 (docs/orbstack-startup.html) が前提。redminectl は最初に docker info を叩いて、繋がらなければ止まる。

$ docker info --format '{{.ServerVersion}}'
29.4.0                          # デーモンに繋がっている
$ lsof -nP -iTCP:3000 -sTCP:LISTEN
                                # 何も出なければポート 3000 は空いている
$ docker compose version
Docker Compose version v5.1.2   # スペース版が使えること (OrbStack 初回起動後に有効)
  • OrbStack が起動している (メニューバーにアイコンが出ている)
  • OrbStack の設定で「ログイン時に起動」を ON にしてある — Mac を再起動しても Redmine が自動で戻るのはこの設定があるとき
  • ポート 3000 を他で使っていない (GitLab は 8080 / 8443 / 2222 なので同居できる)
  • ~/srv のあるディスクに空きがある。目安: DB + 添付ファイル × バックアップ世代数 (既定 14)
docker が command not found のとき

nix-darwin を適用した直後のシェルは PATH が古い。exec zsh -l で開き直す。redminectl もこのメッセージを出して止まる。

2 — 初回セットアップ

コマンドは 1 つ。秘密情報は手で作らない

一度だけ実行
$cd redmine && ./redminectl setup

置き場の作成、.env の生成、起動、HTTP 200 の確認までをまとめて行う。所要 1〜2 分 (イメージの pull を含む)。

順やること結果
1~/srv/redmine/{files,plugins,themes,db} を作るbind mount 先が揃う。既にあれば何もしない
2redmine/.env を生成 (無いときだけ)openssl rand で DB パスワード 48 桁と secret_key_base 128 桁。chmod 600
3docker compose up -ddb が healthy になってから redmine が起動。初回は migration に 30 秒ほど
4http://127.0.0.1:3000/ が 200 を返すまで待つ最長 120 秒。超えたら logs を見るよう案内して止まる
ブラウザで最初にやること

admin / admin でログイン → パスワード変更を求められる → 変更。次に「管理 → 設定 → 全般」で ホスト名を 127.0.0.1:3000 にしておくと、通知メールのリンクが正しくなる。

.env は再生成されない

2 回目以降の setup は既存の .env をそのまま使う。secret_key_base を変えるとセッションと暗号化済み設定 (LDAP パスワード等) が読めなくなるため、意図せず変わらないようにしてある。

状態の置き場

守るべきファイルは 5 つ。git に入るのは 0

リポジトリには定義だけを置き、コンテナが生み出す状態はすべて ~/srv/redmine に出す — GitLab と同じ流儀。バックアップ対象と一致させてあるので、下の表の「backup」列が ✓ のものは redminectl backup で自動的に拾われる。

パス中身gitbackup失うと
~/srv/redmine/db/PostgreSQL のデータ本体 (チケット・Wiki・ユーザー)✗✓ (pg_dump)全チケットが消える
~/srv/redmine/files/チケットや Wiki の添付ファイル✗✓添付へのリンクが 404
~/srv/redmine/plugins/手で置いたプラグイン✗✓起動失敗 (DB にプラグインの表が残るため)
~/srv/redmine/themes/手で置いたテーマ✗✓見た目が既定に戻るだけ
redmine/.envDB パスワード · secret_key_base✗ (.gitignore)✓ (env として)DB に繋げない · セッション全滅
redmine/docker-compose.yaml構成の定義✓—git から取り直せる
置き場を変えたいとき

.env に REDMINE_DATA_DIR=/Volumes/data/redmine のように書く。compose と redminectl の両方がこの値を見る。既に動いているなら down → ディレクトリごと mv → .env 編集 → up。

3 — 日常運用

普段使うのは status と logs。あとは触らない

コマンド何が起きるか使う場面
./redminectl statuscompose ps と HTTP ステータス、データ置き場、バックアップの登録状況を 1 画面に「動いてる?」と思ったとき
./redminectl logs [db]直近 100 行から追いかける。Ctrl-C で抜ける500 が出た · 起動しない
./redminectl restart両コンテナを再起動し、200 が返るまで待つ設定変更後 · 挙動が怪しいとき
./redminectl downコンテナとネットワークを消す。データは残るポートを空けたい · メンテ前
./redminectl upup -d して 200 を待つ。.env が無ければ止まるdown の後
 
$ ./redminectl status
NAME         IMAGE         SERVICE   STATUS
redmine      redmine:6     redmine   Up 3 days
redmine-db   postgres:16   db        Up 3 days (healthy)

HTTP 200  http://127.0.0.1:3000
data  /Users/kasamatsu/srv/redmine
backup schedule: installed (com.ysksm.redmine-backup)
Mac を再起動したら

OrbStack がログイン時に起動 → restart: always の 2 コンテナが自動で戻る。手で up する必要はない。戻っていなければ OrbStack の自動起動設定を疑う。

スリープ

OrbStack は VM ごとスリープする。復帰直後の数秒は応答しないことがあるが、放っておけば戻る。

4 — バックアップ

1 回 = 1 ディレクトリ。DB と添付と .env をセットで

手動で取る
$./redminectl backup

Redmine を止めずに取れる。pg_dump はトランザクション内で一貫したスナップショットを取るので、稼働中でも安全。

~/srv/redmine-backup/
 ├─ 20260912-030000/
 ├─ 20260913-030000/
 └─ 20260914-030000/            # 日付-時刻。新しいものが末尾に並ぶ
      ├─ db.sql.gz              # pg_dump --no-owner を gzip。psql で流し込める平文 SQL
      ├─ files.tar.gz           # files/ plugins/ themes/ をまとめたもの
      └─ env                    # その時点の .env のコピー (600)。復旧時に鍵が合うかの照合に使う

世代管理

新しい順に 14 世代残し、古いものを消す。変えるなら REDMINE_BACKUP_KEEP=30 のように環境変数で。

置き場

既定は ~/srv/redmine-backup。REDMINE_BACKUP_DIR で外付けディスクなどに向けられる。

同じ Mac に置いたままにしない

ディスク故障には無力。rsync や Time Machine の対象に ~/srv/redmine-backup を入れておく。~/srv/redmine/db 自体を Time Machine で拾っても、書き込み途中の壊れたコピーになりやすい。

4 — バックアップ (自動化)

毎晩 03:00、launchd に任せる

macOS の定期実行は cron ではなく launchd。redminectl が ~/Library/LaunchAgents/ に plist を書いて登録するので、plist を手で書く必要はない。

一度だけ実行
$./redminectl schedule-backup

ラベルは com.ysksm.redmine-backup。ログは ~/srv/redmine-backup/launchd.log に追記される。解除は unschedule-backup。

$ launchctl print gui/$(id -u)/com.ysksm.redmine-backup | grep -E 'state|last exit'
	state = not running                 # 待機中。03:00 になると走る
	last exit code = 0                  # 前回が成功していれば 0

$ launchctl kickstart gui/$(id -u)/com.ysksm.redmine-backup
                                    # 今すぐ 1 回走らせて動作確認
$ tail -3 ~/srv/redmine-backup/launchd.log
==> 古い世代を削除 (残す: 14)
  removed /Users/kasamatsu/srv/redmine-backup/20260831-030000
==> 完了: 38M  /Users/kasamatsu/srv/redmine-backup/20260914-030000
launchd の PATH は空っぽ

そのままだと docker が見つからない。plist には /run/current-system/sw/bin (nix-darwin) を先頭にした PATH を明示してある。Homebrew 版に切り替えても /opt/homebrew/bin が入っているので動く。

03:00 に Mac が寝ていたら

StartCalendarInterval は起きたときに 1 回まとめて実行される。スキップはされない。確実に取りたければ「システム設定 → 省エネルギー」でスリープさせない。

6 — 復旧

戻すのも 1 コマンド。ただし DB は作り直す

確認プロンプトあり · 現在の DB を捨てる
$./redminectl restore ~/srv/redmine-backup/20260913-030000

y を打つまで何もしない。backup で作ったディレクトリをそのまま渡す。

1. redmine を stop            # DB への接続を切る (繋がったままだと DROP できない)
2. db だけ up、pg_isready を待つ
3. DROP DATABASE → CREATE DATABASE
4. db.sql.gz を psql に流す
5. files/ plugins/ themes/ を消して tar を展開
6. redmine を up、200 を待つ    # 起動時の migration がスキーマ差分を埋める
.env が違うと警告が出る

バックアップ内の env と今の .env を cmp して、違えば止まらずに警告だけ出す。secret_key_base が違うと DB は戻っても暗号化済み設定が読めない。別の Mac に移すときは先に cp <dir>/env redmine/.env。

新しい Mac へ引っ越す手順

① バックアップディレクトリをコピー → ② リポジトリを clone → ③ cp <dir>/env redmine/.env → ④ setup (空で起動) → ⑤ restore <dir>。

復旧の練習は年に 1 回はやる。バックアップの価値は restore が通って初めて確定する。

5 — 更新

バックアップ → pull → up。migration は勝手に走る

月 1 回、または脆弱性情報が出たとき
$./redminectl update

最初に backup を必ず取る。失敗しても直前のバックアップに restore で戻れる。

$ ./redminectl update
==> DB をダンプ → ~/srv/redmine-backup/20260914-101502/db.sql.gz
==> イメージを更新
 Image redmine:6      Pulled              # 6.0.x → 6.1.x のようなマイナー更新はここで入る
 Image postgres:16    Pulled
==> 再作成 (DB migration は起動時に自動実行される)
 Container redmine    Recreated
==> 起動完了: http://127.0.0.1:3000
REPOSITORY   TAG   SIZE
redmine      6     651MB
postgres     16    438MB
タグは 6 で固定

redmine:6 は 6.x 系の最新を指す。7 が出ても勝手に上がらない。メジャー更新は compose のタグを 7 に書き換えてから update。

postgres は 16 のまま

PostgreSQL のメジャー更新は pg_upgrade が必要で pull では上がらない。やるなら backup → タグ変更 → ~/srv/redmine/db を空に → restore。

戻したいとき

compose のタグを前のバージョン (例 redmine:6.0.5) に固定 → restore で update 直前のバックアップに戻す。migration は不可逆なので DB ごと戻す。

プラグイン · テーマ

置いて、plugins を叩く

$ cd ~/srv/redmine/plugins
$ git clone https://github.com/example/redmine_example.git
$ cd - && ./redminectl plugins
==> プラグインの migration
==> Redmine を再起動して読み込ませる
==> 起動完了: http://127.0.0.1:3000
plugins がやること

rake redmine:plugins:migrate をコンテナ内で実行してから redmine を再起動する。SECRET_KEY_BASE を compose で直接渡しているので、exec 経由の rake でも鍵の不足で落ちない。

gem を要求するプラグインは対象外

公式イメージは起動時に bundle install を試みるが、ネイティブ拡張のビルドが要るものは失敗する。その場合は Dockerfile を書いてイメージを焼く必要がある — この構成では扱わない。

テーマ

~/srv/redmine/themes/ に置くだけ。migration は不要。「管理 → 設定 → 表示」で選ぶ。反映されなければ restart。

外すとき

先に rake redmine:plugins:migrate NAME=redmine_example VERSION=0 で表を消してからディレクトリを削除。順番を逆にすると起動時に落ちる。

まとめ

運用チェックリスト

初回 (一度だけ)

  • OrbStack「ログイン時に起動」を ON
  • ./redminectl setup
  • admin のパスワード変更、ホスト名設定
  • ./redminectl schedule-backup
  • launchctl kickstart で 1 回走らせ、launchd.log を確認

月 1 回

  • ./redminectl status — 2 コンテナが Up、HTTP 200
  • ls ~/srv/redmine-backup | tail -3 — 日付が今日まで続いている
  • ./redminectl update
  • docker image prune で古いイメージを掃除

年 1 回

  • 別ディレクトリ (REDMINE_DATA_DIR を変えて) に restore を試し、ログインできることを確認
  • Redmine / PostgreSQL のメジャーバージョンの EOL を確認
