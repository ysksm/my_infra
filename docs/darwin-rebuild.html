Nix / nix-darwin / macOS 26 · Apple Silicon

darwin-rebuild 解剖図

1 行のコマンドに、7 つのパーツと6 者の提供物が詰まっている。
どこからどこまでが誰のものなのかを、1 つずつほどいていく。

$1sudo 2nix run 3nix-darwin/master4#darwin-rebuild 5-- 6switch 7--flake .#mini

下線の色は「誰が提供しているか」を表す。次のスライドで登場人物を紹介する。

01 — 登場人物

まず、関わっている 6 者を知る

Apple sudo

macOS 標準。/usr/bin/sudo にある OS の一部。

Determinate Systems nix

この Mac に入っている Nix の配布元。nix コマンドの実体。

nix-darwin プロジェクト darwin-rebuild

macOS を宣言的に設定するコミュニティ製のモジュール群。

NixOS / nixpkgs パッケージ定義

10 万個規模のレシピ集。orbstack の「取ってき方」もここ。

OrbStack orb / docker / kubectl

実際に動くバイナリの作者。商用アプリ（unfree ライセンス）。

あなた flake.nix / hosts / modules

~/src/github/my_infra。「何を入れるか」の宣言だけを書く。

ここが勘所

Nix はソフトウェアをほとんど作っていない。「どこから取ってきて、どう置くか」を決めて実行する仕組みで、中身は各社・各プロジェクトのものがそのまま入る。

パーツ 1 / 7

sudo — 管理者権限を借りる

誰のもの？

Apple macOS に最初から入っている /usr/bin/sudo。Nix とは無関係の、ごく普通の UNIX コマンド。

なぜ必要？

このあとの処理が /etc/ 配下の設定、launchd デーモン、/run/current-system を書き換えるため。ユーザー権限では触れない場所。

実行時に出た警告

sudo で root になると、Nix から見たホームディレクトリも root のものに変わる。これは無害で、無視してよい。

$ sudo nix run nix-darwin/master#darwin-rebuild -- switch --flake .#mini
Password:
warning: $HOME ('/Users/') is not owned by you, falling back to
the one defined in the 'passwd' file ('/var/root')

パーツ 2 / 7

nix run — 入れずに、その場で走らせる

この Mac の nix は Determinate Systems 版。上流の Nix をベースにした独自ディストリビューション。

$ nix --version
nix (Determinate Nix 3.22.3) 2.35.2   # 上流 Nix 2.35.2 が中身
サブコマンドビルド実行残る？
nix buildするしない./result が残る
nix profile installするしない恒久的に PATH へ
nix runするする残らない
なぜ run なのか — 鶏と卵

「nix-darwin を入れるためのコマンド」が nix-darwin の中にある。まだ何も入っていないので、一時的に借りてくるしかない。実際、今この Mac には存在しない。

$ which darwin-rebuild
darwin-rebuild not found
$ ls /run/current-system
No such file or directory   # nix-darwin はまだ未適用

パーツ 3 / 7

nix-darwin/master — 省略名が URL に化ける

これは短縮記法。フレークレジストリという名前帳を引いて、本当の場所に解決される。この環境には 39 件の省略名が登録されている。

$ nix registry list | grep nix-darwin
global flake:nix-darwin github:nix-darwin/nix-darwin

$ nix flake metadata nix-darwin/master
Resolved URL:  github:nix-darwin/nix-darwin/master
Locked URL:    github:nix-darwin/nix-darwin/4cff07de74b50e64bdd68cd4e722ab5b6b35ee48
Description:   A collection of darwin modules

master はブランチ名

毎回その時点の最新が取られる。試すには手軽だが、日によって結果が変わりうる。

本番では固定する

このリポジトリでは flake.lock に 4cff07de を記録済み。--flake .#mini 側は常に同じものを使う。

つまり同じ 1 行の中で、nix-darwin を 2 回参照している。nix run 用は最新、設定の評価用は lock 固定。

パーツ 4 / 7

#darwin-rebuild — flake の中のどれか

# の後ろは属性セレクタ。1 つの flake は複数の成果物を持つので、そのどれを指すかを書く。

書き方指しているもの提供者
nix-darwin/master#darwin-rebuild実行できるコマンドnix-darwin
.#orbstackOrbStack のパッケージnixpkgs
.#darwinConfigurations.miniシステム構成そのものあなた
darwin-rebuild の正体

特別なバイナリではなく、nix-darwin が提供するシェルスクリプト。中では「構成を nix build する」→「できたものを有効化する」を順に行っているだけ。

パーツ 5 / 7

-- — 引数の持ち主が変わる境界線

1 行の中に、2 つのプログラムへの指示が混ざっている。その切れ目を示すのが単独の --。UNIX 共通の作法で、Nix 固有のものではない。

sudo nix run nix-darwin/master#darwin-rebuild -- switch --flake .#mini
     └────────── nix への指示 ──────────┘    └── darwin-rebuild への指示 ──┘

これが無いと

nix が switch や --flake を自分宛のオプションだと解釈してしまい、知らないオプションだとしてエラーになる。

同じ作法の例

ls -- -file（-file をオプションでなくファイル名として扱う）、git checkout -- path など。

パーツ 6 / 7

switch — ビルドして、有効化まで進める

nix-darwin が提供するサブコマンド。どこまでやるかで名前が分かれている。

サブコマンドやることシステムは変わる？
check設定を評価してエラーを見る変わらない
buildビルドして ./result を作る変わらない
switchビルド + 有効化 + 次回起動時のデフォルトに設定変わる
やり直せる

適用のたびに「世代」が積まれる。darwin-rebuild --list-generations で一覧、--rollback で 1 つ前に戻せる。壊しても戻れるのが宣言的管理の利点。

パーツ 7 / 7

--flake .#mini — ここだけがあなたの担当

. はカレントディレクトリの flake.nix、mini はその中の darwinConfigurations.mini。このコマンドで唯一、自分が書いたものを指している部分。

~/src/github/my_infra/
├── flake.nix                # darwinConfigurations.mini ← ここが呼ばれる
│     ├─ hosts/mini.nix      # この Mac の設定（OrbStack を有効に）
│     └─ modules/orbstack.nix # OrbStack をどう入れるかの部品
└── flake.lock               # nixpkgs / nix-darwin のバージョン固定
flake の制約

flake は git が追跡しているファイルしか見えない。新しく作った .nix ファイルは git add しないと「not tracked by Git」と怒られる。よくハマるポイント。

03 — 実行されると

何が、誰の手で起きるか

  1. nix-darwin を GitHub から取得してビルドする
    Determinate Nix が実行。初回は数分かかる
  2. mini の設定を評価し、システム世代を /nix/store にビルド
    あなたの flake の内容が、nixpkgs のレシピを使って形になる
  3. /run/current-system を新しい世代に向け替える（activation）
    darwin-rebuild が実行。sudo が要るのはこの工程
  4. /Applications/Nix Apps/OrbStack.app が現れる
    nix-darwin は通常の /Applications ではなく専用フォルダに置く
  5. PATH に orb orbctl docker kubectl が入る
    中身は OrbStack のバイナリそのもの

04 — 答え合わせ

結局どのコマンドが誰のものか

ビルド済みパッケージの bin/ を覗くと、実体がはっきり見える。中身はすべて OrbStack.app への symlink。

$ ls -l /nix/store/3086sz9...-orbstack-2.2.3-20963/bin/
docker         -> ../Applications/OrbStack.app/Contents/MacOS/xbin/docker-tools
docker-buildx  -> ../Applications/OrbStack.app/Contents/MacOS/xbin/docker-tools
docker-compose -> ../Applications/OrbStack.app/Contents/MacOS/xbin/docker-tools
kubectl        -> ../Applications/OrbStack.app/Contents/MacOS/xbin/kubectl
orb            -> ../Applications/OrbStack.app/.../MacOS/scli
orbctl         -> ../Applications/OrbStack.app/.../MacOS/scli
コマンド提供者備考
sudoApplemacOS 標準
nixDeterminate Systems3.22.3（上流 Nix 2.35.2）
darwin-rebuildnix-darwin適用後に PATH へ入る
orb / orbctlOrbStack同じ scli への 2 つの名前
docker 系 3 つOrbStackすべて docker-tools 1 本の別名
kubectlOrbStackアプリに同梱
nixpkgs の役割

nixpkgs は Docker も OrbStack も作っていない。公式の .dmg を取ってきて展開し、bin/ に symlink を張る——その手順書を提供しているだけ。

05 — つまずいた点

Determinate Nix と nix-darwin の縄張り争い

$ sudo nix run nix-darwin/master#darwin-rebuild -- switch --flake .#mini
building the system configuration...
error: Determinate detected, aborting activation

Determinate uses its own daemon to manage the Nix installation that
conflicts with nix-darwin's native Nix management.

原因

Determinate と nix-darwin が、どちらも「Nix 本体の面倒を見る」機能を持っている。二重管理になるので nix-darwin 側が中断する。

対処

hosts/mini.nix に 1 行足して、nix-darwin 側の Nix 管理を降ろす。

# hosts/mini.nix
nix.enable = false;
代償

nix.settings や Linux ビルダーなど nix.* の設定は使えなくなる。Nix 自体の設定は Determinate 側（/etc/nix/nix.custom.conf や determinate-nixd）で行う。OrbStack を入れる用途には影響しない。

06 — まとめ

この長さが必要なのは初回だけ

適用が済むと darwin-rebuild 自体が PATH に入るので、2 回目以降はここまで短くなる。

# 初回（darwin-rebuild がまだ無いので借りてくる）
$ sudo nix run nix-darwin/master#darwin-rebuild -- switch --flake .#mini

# 2 回目以降
$ sudo darwin-rebuild switch --flake .#mini

覚えておくこと

  • Homebrew cask 版の OrbStack があれば先に削除する
  • 初回起動時、特権ヘルパーのインストールを求められる
  • system.stateVersion = 6 は適用後に変更しない

更新するとき

  • nix flake update で nixpkgs / nix-darwin を更新
  • もう一度 switch すれば新しい世代になる
  • 問題があれば --rollback で戻す
